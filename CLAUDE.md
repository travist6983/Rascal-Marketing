# Vellum marketing site

Static site, zero dependencies at runtime. Pages live in `src/pages/`, partials in
`src/partials/`, and `node scripts/build.mjs` (npm run build) renders everything to
`dist/`. Canonical content is `docs/site-content.md`; SEO build requirements are
`docs/seo-plan.md`.

## Markdown twins are part of every edit

Every indexable page also ships as Markdown for LLMs: `route + ".md"` (e.g.
`/pricing.md`), plus `/llms.txt` (the index) and `/llms-full.txt` (whole site, one
file). **Any edit to page content must be followed by a rebuild so these stay in
sync** — they are generated by `scripts/markdown.mjs` during `npm run build`, from
the same rendered bodies as the HTML.

- Never hand-edit a `.md` twin or `llms*.txt` — edit the page in `src/pages/` and
  rebuild. `dist/` is gitignored and the Pages workflow rebuilds on deploy, so the
  live twins can only drift if you skip the build locally and trust stale output.
- New pages get a twin automatically from their front matter. Add the route to the
  `GROUPS` list in `build.mjs` so it lands in the right `llms.txt` section
  (unlisted routes fall into a generic "Pages" group).
- `noindex: true` pages (thanks, 404) deliberately get no twin.

## Before committing

Run `npm run build && npm run check`. The check suite is the launch break-test:
it verifies the twins exist and parse clean (no leaked HTML, no unresolved
tokens, no pronoun-token leaks), plus titles, headings, links, alt text, 320px
overflow, and the form ladder in real Chromium.

## Other conventions that must survive edits

- Every `{{TOKEN}}` resolves from `site.config.json` — PRODUCT is "Vellum";
  `{{DOMAIN}}` stays literal until a domain is bought. Never hardcode the name,
  prices, or the prompt count in markup.
- The prompt library is generated: `npm run prompts` regenerates
  `src/partials/prompt-library.html` from Project-Rascal's seed. Anchor ids are
  frozen in `scripts/prompt-anchors.json` — never renumber them.
- No red anywhere; an absent feature is an em dash. ✓ ticks affirm promises,
  never anti-features. Competitor claims carry `verified-on` HTML comments.
- Voice rules live in `docs/site-content.md` §Voice and §"Do not write" — they
  are binding for any copy change, including the Markdown twins by construction.
